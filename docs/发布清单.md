# 发布清单（P7）

> 目的：把"可发布"变成**可逐条执行、每步都能验证**的清单，而不是靠记忆。
> 每条都给出命令与判据；`[ ]` 表示待执行，执行完在括号里记结果。

## 0. 前置：本机构建产物就位

- [ ] **主程序**：`wails build`（或 `go build -tags desktop,production`）→ `build\bin\MelodyMate.exe`
- [ ] **引擎**：`cd engine; cmake --build build --config Release --target melodymate-engine`
      → 拷到 `bin\melodymate-engine.exe`（**先杀掉运行中的引擎**，否则文件被占用）
- [ ] **插件工具链**：`go build -o mm.exe ./cmd/mm`（发行包要求它**与主程序同目录**：
      `MelodyMate.iss` 的 `[Files]` 已带 `mm.exe`；AI 工具与设置页安装流程都找它）
- [ ] **MM SDK**：`engine\mm-sdk\`（只带 `include/mm/mm.h` + `CMakeLists.txt` + `examples`；
      `mm build` 默认在 `<主程序目录>\engine\mm-sdk` 下找 SDK）
- [ ] **随包音色库**：`Library\soundfonts\GeneralUser GS v1.471.sf2`（+ LICENSE）
- [ ] **知识库**：`Library\*.md`

## 1. 安装包

- [ ] `iscc MelodyMate.iss` → 生成安装程序
- [ ] 装机后核对目录结构（缺一个都会导致功能静默降级）：

```
{app}\MelodyMate.exe
{app}\bin\melodymate-engine.exe
{app}\mm.exe                     ← P6：插件工具链
{app}\engine\mm-sdk\include\mm\mm.h   ← P6：编译插件
{app}\engine\mm-sdk\examples\gain|synth
{app}\Library\*.md
{app}\Library\soundfonts\GeneralUser GS v1.471.sf2
{app}\Library\plugins\README.txt
```

- [ ] 卸载程序保留用户数据（`Library\soundfonts`、`Library\plugins`、工程目录），只清程序文件

## 2. 干净机验收（**不能用开发机代替**）

- [ ] 装完后启动：首屏正常、无 JS 报错（F12 控制台）、音频设备可枚举
- [ ] **老数据迁移**：把 v3.1.x 的数据根整体拷入，逐项确认：
      - [ ] 设置迁移（老 `materialDirs` → 采样包条目）
      - [ ] 音源注册表可重建（SF2 重新扫描入册；MM 插件点「↻ 同步已安装插件」）
      - [ ] 老工程能打开（arrangement v1 → v2 自动升级，轨/音符/循环/bpm 保留）
      - [ ] 老工程里"音源只剩 path"的轨显示「♪ ⚠ 音源缺失」而不是静音无提示
      - [ ] 升级后工程可继续 AI 编曲（ops 路径）并落盘
- [ ] **插件全链路**（干净机上没有开发期缓存）：
      - [ ] 引擎分区扫描 VST3 → 列表有内容 → 装载效果器 → 参数可读 → 原生编辑器打开
      - [ ] 设置页安装 `mm.exe` 自带示例（`engine\mm-sdk\examples\gain\*.mm` 打包后）
            → 预览能力 → 勾选授权 → 安装 → 出现在声音管理
      - [ ] 对话里让 AI 创建插件（`mm_create_plugin` → `mm_build_plugin` → `mm_install_plugin`）
            → 装载 → 参数可调 → MM 承载窗能打开并改参数
- [ ] **崩溃隔离**：故意装一个会崩的第三方 VST3（如 Krush）→ 引擎崩 → 主程序自动重启引擎并提示
- [ ] 双主题 + 键盘：设置/编曲/素材库/混音台四个界面各走一次（Tab/↑↓/Enter/Esc/F9）
- [ ] `prefers-reduced-motion` 打开（系统设置）→ 无动效但功能完整
