## 一、问题诊断结论

### 确定根因（P0）：引擎从未加载过 SF2，原生实时演奏路径必然静默

链路证据：
- 钢琴卷帘所有实时发声（点击音符 [pianoroll.js:1768](file:///d:/pyx/AI_MIDI-go/frontend/js/pianoroll/pianoroll.js#L1768)、MIDI 输入 [3126](file:///d:/pyx/AI_MIDI-go/frontend/js/pianoroll/pianoroll.js#L3126)）在 Wails 模式下走原生路径（synth.js noteOn 的 `when === undefined` 分支）→ `EngineBridge.noteOn` → 二进制 Midi 帧 → 引擎 `SynthEngine::noteOn` 入环；
- 但引擎音频回调 [EngineAudioDevice.cpp:146](file:///d:/pyx/AI_MIDI-go/engine/Source/Audio/EngineAudioDevice.cpp#L146)：`synth_.render()` 在 `synth_ == nullptr`（**从未 loadSoundFont**）时直接返回 false → 回退测试音分支 → toneOn=false → **输出静音**；
- 全仓只有「上传新 SF2」一条路径会调 `loadSoundFont`（handler_soundfont.go:70），启动时无任何加载逻辑。设置页测试音是引擎内置三角波，不需要 SF2，所以唯独它能响。

### 待运行时验证（P1）：Web Audio 调度路径

钢琴卷帘走带播放（带 `when`）与编曲窗播放/素材试听走 Web Audio，静态审查链路完整（SharedAudio 恢复 → 调度心跳 → osc/BufferSource.start(when)）。但用户反馈"没一处能播"，且 audio_engine.js 注释残留「SoundFontPlayer 远期调度问题根因待查」，需用 audio_selftest.html 实测裁决；发现具体故障则就地修复。

### M3 现状（本计划第二部分）

- `Transport.h`（play/stop/locate/setTempo + 50Hz timecode 推送）**已实现未接线**：Main.cpp 无对应 IPC 方法，sender 未注入；
- `MixerGraph.h`（32 轨 gain/pan/mute/solo + 主增益）**已实现未接线**：`setTrackMix` IPC 已通但混音图不在渲染链上（synth 直写输出，绕过 mixer）；
- `EngineAudioDevice.h` 已预留 `setTimecodeSender` / `transport()` / `mixer()` 访问器——接线点全部就绪；
- 前端 `updateTrackMix`（audio_engine.js:554）已写好但 arrange.js 从未调用。

**文件**：[internal/engine/supervisor.go](file:///d:/pyx/AI_MIDI-go/internal/engine/supervisor.go)

## 三、Part B：M3 阶段一——走带与混音图接线

> 范围界定：本阶段打通「Transport/MixerGraph 全链路 + Go/前端桥 + 混音同步」基建；**编曲窗原生调度渲染（音符/素材剪辑进引擎）属阶段二，不做**。编曲窗播放仍走 Web Audio 不变。

### B1. 引擎 Main.cpp：走带 IPC + timecode 推送接线

**文件**：[engine/Source/Main.cpp](file:///d:/pyx/AI_MIDI-go/engine/Source/Main.cpp)

新增 JSON 方法（均在管道线程直接调 transport_，原子量安全）：

| 方法 | params | 行为 |
|---|---|---|
| `play` | `{}` | `transport().play()`，返回 `{}` |
| `stop` | `{}` | `transport().stop()`，返回 `{}` |
| `locate` | `{"beat": <double>}` | `transport().locate(beat)`，返回 `{}` |
| `setTempo` | `{"bpm": <double>}` | `transport().setTempo(bpm)`，返回 `{}` |
| `timecode` | `{}` | 返回 `{"beat":..,"playing":..,"bpm":..,"samplePos":..}`（拉取式，供前端轮询） |

timecode 推送接线（`main()` 中管道 start 后）：
```cpp
pipe.setTimecodeSender([&pipe](const void* data, int size) {
    pipe.writeFrame(aimidi::ipc::MsgType::Timecode,
                    static_cast<const uint8_t*>(data), static_cast<size_t>(size));
});
```
（EngineAudioDevice 已有 `setTimecodeSender` 转发；Transport payload 25 字节布局与协议注释一致。）

### B2. 引擎渲染链接入 MixerGraph

**文件**：[engine/Source/Audio/EngineAudioDevice.cpp/.h](file:///d:/pyx/AI_MIDI-go/engine/Source/Audio/EngineAudioDevice.cpp) + [MixerGraph.h](file:///d:/pyx/AI_MIDI-go/engine/Source/Audio/MixerGraph.h)

- EngineAudioDevice 增加私有成员 `std::vector<juce::AudioBuffer<float>> trackBuffers_`（1 轨立体声，`audioDeviceAboutToStart` 里按设备采样率/最大块长 setSize）；
- 回调改为：`synth_.render(指向 trackBuffers_[0] 的双通道指针, 2, numSamples)` 成功 → `mixer_.process(outputChannelData, totalNumOutputChannels, numSamples, trackBuffers_)` → return；render 失败（未加载音色）仍走测试音分支直写输出；

- 已知取舍（阶段二再精化）：合成器暂挂 track 0；前端编曲轨 index 与引擎轨 index 的语义映射在原生调度落地时统一。

## 四、关键决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 原生静默修法 | Go 会话建立后自动加载默认 SF2（非引擎内置音色） | 音色文件已在 Library/soundfonts；引擎保持无状态、快照由 Go 维护（对齐既有 lastApply 设计） |
| timecode 消费方式 | 双轨：引擎 50Hz 推送帧 + Go 在请求事务中锁存最新帧；前端需要时轮询 `timecode` 请求/绑定 | 同步管道句柄不允许常驻并发读（旧注释明确的死锁约束），常驻读线程需切重叠 I/O，留待后续；锁存方案零成本兼容现有串行模型 |
| M3 阶段一边界 | Transport/MixerGraph 接线 + Go/前端桥 + 混音同步；**不做**编曲窗原生调度 | 原生调度需把音符/剪辑/循环展开整体搬进 C++，是阶段二主体；先把已写好的三块 WIP 接活可独立验收 |
| updateTrackMix 接线时机 | 本阶段接入 applyMixSafe | 管线完整性（setTrackMix→MixerGraph 全链路可验），语义映射已知粗糙、阶段二统一 |
| Web Audio 疑点 | 不预改代码，实测裁决后修 | 静态链路完整；盲改反而可能引入回归 |
