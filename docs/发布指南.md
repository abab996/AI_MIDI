# AI_MIDI 发布指南

> 面向维护者的完整发版流程。以 v3.0.0 首发实战为蓝本，覆盖版本号、构建、
> 自测、推送、Release 发布、R2 对象存储桶更新与踩坑清单。新版本发布照此流程逐步执行即可。

---

## 0. 产物策略（固定约定）

| 平台 | 发布物 | 命名 |
| --- | --- | --- |
| Windows | **仅安装包**（Inno Setup，含 JUCE 引擎），不分发便携压缩包 | `AI_MIDI_Setup_<版本>_windows_amd64.exe` |
| Linux | **仅 tar.gz 压缩包**（Web Audio 降级，无引擎） | `AI_MIDI_v<版本>_linux_amd64.tar.gz` |

发布物统一暂存到 `dist/release/`（已被 gitignore，不入库）。

**分发渠道（双渠道）**：GitHub Release（主渠道）+ R2 对象存储桶（下载镜像 + 应用内自动更新数据源，见第 8 节）。

| 文件 | 位置 | 说明 |
| --- | --- | --- |

## 3. 构建

```bat
:: 0) 默认音色（GeneralUser GS v1.471，约 27 MB，iss 硬性要求缺失即打包失败；
::    已存在则跳过。文件不入 git，构建机首次必须执行）
tools\fetch_soundfont.bat

:: 1) Windows 主程序（产物 build\bin\AI_MIDI.exe，前端已内嵌）
wails build

:: 1.5) 组装 build\bin 自测布局（引擎/知识库/默认音色复制到产物旁，
::      使 build\bin\AI_MIDI.exe 可直接双击自测打包布局）
tools\assemble_buildbin.bat

:: 2) Linux 二进制（浏览器模式）
GOOS=linux GOARCH=amd64 go build -trimpath -ldflags "-s -w" -o build/release/AI_MIDI-linux-amd64 .

:: 3) 安装包（产物 dist\installer\AI_MIDI_Setup_<版本>_windows_amd64.exe）
::    前置：tools\build_engine.bat 产出 bin\aimidi-engine.exe（iss 对其硬性要求，
::    缺失时打包失败——不再静默漏装引擎）
"C:\Users\<你>\AppData\Local\Programs\Inno Setup 6\ISCC.exe" AI_MIDI.iss
```

注意：ISCC 必须在**仓库根目录**执行（脚本内引用相对路径）。

## 4. 发布物组装（dist/release/）

```bash
# Windows 安装包
cp dist/installer/AI_MIDI_Setup_<版本>_windows_amd64.exe dist/release/

# Linux 包：AI_MIDI + RUN.sh + settings.example.json + README.md + README_zh.md + LICENSE
mkdir -p dist/release/AI_MIDI_v<版本>_linux_amd64
cp build/release/AI_MIDI-linux-amd64 dist/release/AI_MIDI_v<版本>_linux_amd64/AI_MIDI
cp RUN.sh settings.example.json README.md README_zh.md LICENSE dist/release/AI_MIDI_v<版本>_linux_amd64/
chmod +x dist/release/AI_MIDI_v<版本>_linux_amd64/{AI_MIDI,RUN.sh}
cd dist/release && tar -czf AI_MIDI_v<版本>_linux_amd64.tar.gz AI_MIDI_v<版本>_linux_amd64
```

## 5. 发布物自测（不可跳过）

- [ ] 双击安装包完整走一遍：安装 → 首次启动使用声明 → 设置页 → **切 ASIO 驱动** → 卸载
- [ ] ASIO 预期行为：正常驱动 2-5 秒切换成功；慢驱动（ASIO Link Pro 首开 10-20s+）
      在 60 秒时限内应能成功；真卡死超时提示「<设备名> 未响应（已回退到上次可用设备）」
      且 settings.json 被回写——**不应出现假死或"检测中"卡死**
- [ ] 开箱即有声：安装后不插任何音色，钢琴窗/编曲窗播放应直接出声
      （合成波音色走引擎内置波形声部；SF2 轨回退逐轨浏览器渲染），两个播放头都走
- [ ] 驱动控制面板：设置页「打开声卡控制面板」应立即返回；面板开着 >40s 引擎不被杀；
      面板内改缓冲区在关闭面板后生效（设置页延迟数值变化）
- [ ] 卸载后确认用户数据保留、开始菜单/桌面快捷方式清理干净
- [ ] Linux 包在目标环境验证启动（或至少 `file AI_MIDI` 确认 ELF x86-64）

## 8. R2 对象存储桶（下载镜像 + 自动更新清单）

> 自 **v3.1.0** 起应用内置自动更新（`internal/update`），启动时拉取桶内
> `update.json` 比较版本；桶同时作为发布物的下载镜像。本节流程**每次发版必做**。
>
> ⚠️ **桶不会随发布自动更新**：CI（`ci.yml`）只做构建与测试，`gh release create`
> 只发布 GitHub，二者均不触碰 R2——本节步骤全部手动执行。漏掉本节会出现
> "GitHub 上已发布、但旧版本用户应用内收不到提示、『立即更新』直链 404"的假发布。
>
> 版本注记：v3.0.4 从未发布（无 tag、无产物），自动更新代码在 Optimize 分支
> 随 v3.1.0 首发，旧文档中"≥ v3.0.4 起"一律指 v3.1.0。

### 8.1 桶与访问方式

| 项 | 值 |
| --- | --- |
| 平台 / 桶名 | Cloudflare R2 / `aimidi` |
| 公开下载域名 | `https://aimidi-r2.baimoo.top`（桶绑定的自定义域，匿名可读） |
| S3 端点 | `https://2636b485e77a6e30d09a668711b4e2b5.r2.cloudflarestorage.com`（**不可匿名读**，仅签名访问） |
| 客户端 | rclone（`winget install Rclone.Rclone`），remote 名 `r2`，凭据在本机 `%APPDATA%\rclone\rclone.conf` |

rclone remote 重建命令（换机器时；密钥在 Cloudflare 控制台 R2 → Manage R2 API Tokens
创建，只授 aimidi 桶 Object Read & Write）：

```bash
rclone config create r2 s3 provider=Cloudflare \
  access_key_id=<AccessKeyID> secret_access_key=<SecretAccessKey> \
  endpoint=https://2636b485e77a6e30d09a668711b4e2b5.r2.cloudflarestorage.com
```

注意 endpoint **不含桶名**，桶写在目标路径里（`r2:aimidi/...`）。

### 8.2 桶内结构约定

```
update.json                                 ← 自动更新清单（应用启动时拉取）
release/
  AI_MIDI_Setup_<版本>_windows_amd64.exe     ← 各版本安装包
  AI_MIDI_v<版本>_linux_amd64.tar.gz         ← 各版本 Linux 包
  AI_MIDI_v<版本>_linux_amd64/…              ← 解压版目录（惯例保留）
  RELEASE_NOTES_v<版本>.md
  latest.json                                 ← 旧更新机制遗留（已废弃，无代码引用，见下文）
```

（旧 `Version.txt` 已废除，被 `update.json` 取代。
`release/latest.json` 是同一时代的另一遗留文件（实测内容自相矛盾：version 指
3.0.3 而 linux 指向 3.0.2 包），Go、前端与原版 Python 后端均无任何代码引用它——
**已废弃，无需维护**，下次整理桶时可直接删除。）

### 8.3 发版时的桶内更新步骤

```bash
# 1) 上传发布物本体（下载链接指向它们）
rclone copyto "dist/release/AI_MIDI_Setup_<版本>_windows_amd64.exe" \
  "r2:aimidi/release/AI_MIDI_Setup_<版本>_windows_amd64.exe"
rclone copyto "dist/release/AI_MIDI_v<版本>_linux_amd64.tar.gz" \
  "r2:aimidi/release/AI_MIDI_v<版本>_linux_amd64.tar.gz"
rclone copy "dist/release/AI_MIDI_v<版本>_linux_amd64" "r2:aimidi/release/AI_MIDI_v<版本>_linux_amd64"
rclone copyto "dist/release/RELEASE_NOTES_v<版本>.md" "r2:aimidi/release/RELEASE_NOTES_v<版本>.md"

# 2) 计算安装包 sha256（写入清单，应用内下载完成后自动校验）
SHA=$(sha256sum "dist/release/AI_MIDI_Setup_<版本>_windows_amd64.exe" | cut -d' ' -f1)

# 3) 编辑 dist/release/update.json（字段见 8.4；notes 写本次更新日志 markdown）

# 4) 上传清单 —— --metadata-set 必带！原因见 8.5
rclone copyto dist/release/update.json r2:aimidi/update.json \
  --metadata-set "cache-control=no-store" \
  --metadata-set "content-type=application/json; charset=utf-8"

# 5) 验证（curl 必查，不要只看 rclone 上传成功）
curl -s "https://aimidi-r2.baimoo.top/update.json" | python -m json.tool   # version 必须是新版本
curl -sI "https://aimidi-r2.baimoo.top/release/AI_MIDI_Setup_<版本>_windows_amd64.exe" | grep -i content-length
```

### 8.4 update.json 字段说明

```json
{
  "version": "3.1.0",
  "date": "2026-09-06",
  "mandatory": false,
  "notes": "## v3.1.0\n\n- 更新日志 markdown，展示在「更新日志」弹窗",
  "downloads": {
    "windows": "https://aimidi-r2.baimoo.top/release/AI_MIDI_Setup_3.1.0_windows_amd64.exe",
    "linux": "https://aimidi-r2.baimoo.top/release/AI_MIDI_v3.1.0_linux_amd64.tar.gz"
  },
  "sha256_windows": "<第 2 步算出的哈希>"
}
```

| 字段 | 说明 |
| --- | --- |
| `version` | 最新版本号；应用与自身 `AppVersion` 做数值分段比较，大于才有更新提示 |
| `date` | 更新日期（YYYY-MM-DD），显示在更新卡片上 |
| `mandatory` | **必要更新开关，慎用**。`true` 时所有带检查功能的旧版本（≥ v3.1.0）被全屏不可关遮罩拦截，且后端对写操作返回 426，直到完成升级；设回 `false` 或发布更高版本即解除。v3.0.3 及之前已发布的版本没有检查代码，不受影响 |
| `notes` | 更新日志（markdown），「更新日志」按钮弹窗内渲染（前端已做 HTML 转义） |
| `downloads` | 按 GOOS 的公开下载直链（自定义域名 + `/release/` 文件名）；「立即更新」只使用清单内的链接 |
| `sha256_windows` | Windows 安装包 sha256；应用内下载完成后校验，不匹配按下载失败处理。**换安装包必须同步换哈希** |

### 8.5 关键坑：自定义域名的 CDN 缓存

桶绑定的自定义域名走 Cloudflare CDN，**对象更新后边缘节点可能继续返回旧内容**
（实测：桶里已改为 9.9.9，域名仍返回旧版 3.0.3）。两层防护，缺一不可：

1. **清单对象必须带 `Cache-Control: no-store` 元数据**——上文的
   `--metadata-set "cache-control=no-store"` 就是做这个；漏掉会让用户拿到旧清单；
2. 应用拉取时自带唯一查询参数穿透缓存（`internal/update` 已实现，无需操作）。

验证元数据是否生效：`curl -sI https://aimidi-r2.baimoo.top/update.json | grep -i cache-control`。

## 10. 踩坑清单（实战记录）

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| exe 被占用 | `quick_build.bat` 复制失败但静默继续，重启仍是旧程序 | 脚本已改为显式报错；发布前先关应用 |
| 系统清理器删文件 | `%TEMP%` 下的脚本/目录几秒内消失 | 一切产物与脚本放 `dist/` 下，勿用 `%TEMP%` |
| GitHub 连接重置 | push/gh api 报 `Connection was reset` / `EOF` | 开 VPN 重试；`gh` 与 `git` 走同一网络 |
| Linux CI 挂在路径测试 | `C:\...` 在 Linux 不是绝对路径 | 路径类断言用 `filepath.Join(os.TempDir(), ...)` 跨平台写法 |
| ASIO Link Pro 卡死 | 切驱动后引擎无响应（驱动内部死锁，CPU≈0） | 已实现 60s 超时（`applySetupTimeout`，15s 会把慢驱动的正常首开误判为卡死）+「未响应」提示 + 自动回退上一个可用设备；勿在提示后反复重试 |
| 管道读写并发死锁 | 握手/请求"写入超时" | 命名管道为同步句柄，**禁止读写并发**——客户端必须保持"写完再读"的事务模型 |
| gofmt 大面积报警 | `gofmt -l` 列出整文件 | 多为 CRLF 检出行尾误报，提交时按 .gitattributes 归一，无需处理 |
| R2 自定义域 CDN 缓存旧清单 | 桶里 update.json 已更新，`aimidi-r2.baimoo.top` 仍返回旧版本（v3.0.3 发版实测踩中） | 上传清单必带 `--metadata-set "cache-control=no-store"`（第 8 节步骤 4）；应用拉取已内置唯一参数穿透缓存。上传后必须 curl 域名验证，别只看 rclone 成功 |
| wrangler 偶发 libuv 崩溃 | `r2 object put` 报 `Assertion failed: UV_HANDLE_CLOSING` 且未上传 | 改用 rclone（S3 通道稳定）；缓存头用 `--metadata-set` 设置 |
| R2 桶不随发布自动更新 | CI 与 `gh release create` 均不触碰桶：只发 GitHub 会得到"假发布"——GitHub 显示新版，但旧用户应用内无提示、清单缺新链接（v3.1.0 发版前实测桶与清单均停在 3.0.3，而本地 3.1.0 产物早已构建） | 第 8 节为纯手动流程，每次发版必做；发布后按第 9 节 curl 清单与安装包验证，勿以 GitHub 页面为准 |

## 11. 引擎侧遗留备忘（下次迭代）

- `EngineAudioDevice::applySetup` 在 JUCE 消息线程同步打开驱动，坏驱动会永久阻塞
  消息线程——根治需改为异步打开 + 超时探活（需重建 JUCE 工程）；
- 引擎管道断开后 `engineReady` 不自动复位，依赖 hello 重置；
- Go 侧已用 60s 超时 +「未响应」提示 + 自愈回退兜底（见 `internal/engine/supervisor.go`
  的 `lastGood` / `applySetupTimeout`）。
