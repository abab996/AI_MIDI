## 1. 设计目标与三层体系

### 1.1 要解决的问题

P1 之前，音源信息分散在三处：钢琴窗弹窗（IndexedDB）、机架导入（扫目录）、设置页只有一行状态文本；磁盘上的 `Library/soundfonts/*.sf2` 是"真源"却没有任何清单，默认音色只能靠"目录按名排序取首个"。声音管理把这件事收敛成**一份注册表**：

- 只有一个事实源：`Library/registry.json`（`soundlib.FilePath()`）；
- 磁盘是元数据的来源，注册表是**可重建的缓存**——文件损坏或删掉都能从磁盘与设置重新生成（`internal/soundlib/store.go` 的 `Load` 注释与 `migrate.go` 的幂等迁移）；
- 所有消费方（输出机架、素材库「音源」页签、钢琴窗音色、设置页）都从 `frontend/src/soundlib.ts` 的全局 `SoundRegistry` 取候选，不再各自枚举磁盘或 IndexedDB。

### 1.2 三层体系

```
① 声音管理（全局注册表：Library/registry.json = 唯一事实源）
   kind = sf2 | samplepack | vst3 | mm
   入口：设置页「声音管理」页签（搜索/排序/添加/重扫/启停/删除/详情/试听/能力授权）
        │  添加 · 扫描 · 导入 · 启停 · 删除（含 ✨AI 徽标、能力清单与哈希）
        ▼
② 输出机架（项目级乐器箱，存 arrangement.json 的 rack.items）
   从注册表挑选音源进架；轨道与钢琴窗的音源只能来自机架条目引用
        │  条目 = { id, sourceId, presetId, name, pinned }
        ▼
③ 使用点
   ├─ 编曲轨：track.source = { itemId, presetId }（v2 引用，不再存 wave/tone/libId）
   ├─ 钢琴窗音色：arrangement.pianoRoll = { itemId, presetId }
   ├─ 素材库「音源」页签：注册表浏览（拖到轨道 = 分配并自动入架）
   └─ 混音台 FX 槽 / 素材库「效果器」页签：注册表里的 effect 类插件
```

原则一句话：**注册表管"有什么"，机架管"这个项目用什么"，轨道/卷帘管"这一轨用什么"。**

### 1.3 边界（以代码为准）

| 事项 | 现状 |
| :--- | :--- |
| 采样目录的双视角 | 注册表里的 `samplepack` 条目（名称/标签/启停）与历史沿用至今的 `settings.MaterialDirs` 并存：注册表写入时**回写** `MaterialDirs`，启动迁移时把 `MaterialDirs` 里新增的目录**并入**条目。素材树（`GET /api/arrangement/dirs`）仍读 `MaterialDirs`；`soundlib.DirsForPack()` 是迁移期的合并出口（注册表启用目录 + legacy 目录），当前没有调用点 |
| VST3 条目 | 设置页的「扫描 VST3 插件目录」走引擎扫描（`POST /api/engine/plugins/scan`），结果存在引擎侧、由混音台直接读；**扫描结果不写入音源注册表**，所以「VST 插件」分组常驻空态引导 |
| MM 条目 | 安装/同步后写入注册表（`kind=mm`、`origin=ai|user`、`capabilities`、`hash`、`classUid=<插件 id>`），出现在声音管理、素材库「音源」与「效果器」页签 |
| 插件条目的使用限制 | 机架里的 `vst3`/`mm` 条目**不能**直接分配到轨道（`assignRackItem` 会提示走混音台 FX 槽装载） |
| 试听 | 走引擎 29 试听轨（`EngineBridge.PREVIEW_TRACK`），**不做**内置预览播放器；引擎未就绪时明确提示「音频引擎未就绪，试听不可用」 |

## 2. `Library/registry.json` 完整字段表

### 2.1 根结构

```jsonc
{
  "version": 1,          // RegistryVersion，当前恒为 1
  "sources": [ /* Source[]，落盘前按 kind → 名称 排序 */ ]
}
```

文件位置：`<数据根>/Library/registry.json`（`soundlib.FilePath()`；数据根 = 主程序所在目录，`config.ProjectRoot`）。落盘格式是 `json.MarshalIndent(reg, "", "  ")`，写回时**总是重排**（`SortSources`：`sf2 → samplepack → vst3 → mm → 其它`，同 kind 内按名称小写升序）。

### 2.2 `sources[]`（`soundlib.Source`）

| 字段 | JSON 类型 | 含义与取值 | 由谁写 |
| :--- | :--- | :--- | :--- |
| `id` | string | 条目稳定 id（见 §3.3）。一旦生成不可改（`Update` 会强制写回原 id），前端持久化的引用靠它 | `Add`（调用方给或 `makeID` 生成）、`EnsureSF2Source`、MM 同步（`<插件 id 点换下划线>@<版本>`） |
| `kind` | string | `sf2` / `samplepack` / `vst3` / `mm`（常量 `KindSF2/KindSamplePack/KindVST3/KindMM`） | 各写入路径；`normalizeSource` 统一转小写并去空格 |
| `name` | string | 显示名。SF2 缺省用文件名（去扩展名），采样包缺省用目录名，MM 用 manifest 的 `name` | 上传/登记/同步/界面重命名 |
| `vendor` | string | 厂商（供应商）。SF2 与采样包通常为空 | 登记时传入、界面重命名、MM 同步取 manifest |
| `origin` | string | `builtin` / `user` / `ai`；空值被归一化为 `user`。`ai` → 界面显示 ✨AI 徽标 | 上传/登记默认 `user`；`EnsureSF2Source` 与启动迁移对 GeneralUser GS 判 `builtin`；MM 同步按 `author.type=="ai"` 判 `ai` |
| `path` | string | **文件类**音源的路径（sf2/vst3/mm）。数据根（`config.ProjectRoot`）之内记相对路径（正斜杠），根外记绝对路径；见 §3.4 | `normalizeSource` 用 `StorePath(ResolvePath(...))` 规范化；`samplepack` 恒为空 |
| `dirs` | string[] | **采样包**的目录列表（绝对路径、去重、大小写不敏感去重）。其它 kind 恒为空 | 登记采样包、界面改目录、启动迁移 |
| `category` | string | 插件用途：`instrument` / `effect`。仅 `vst3`/`mm` 有意义（缺省归一化为 `instrument`） | MM 同步取 manifest 的 `kind`；其它路径按需 |
| `classUid` | string | `vst3`/`mm` 的插件标识。MM 存**带点的插件 id**，`mm-ui.html?plugin=<classUid>` 与卸载接口都用它 | MM 同步 |
| `capabilities` | string[] | 能力声明：`files` / `network` / `threads` / `midi_out`（安装时已由用户确认） | MM 同步取 manifest |
| `hash` | string | 代表性 sha256（`mmHashOf` 取 `hash.files` 里第一个值）。SF2/采样包为空 | MM 同步 |
| `ai` | 对象 | `{"author": "...", "createdBy": "..."}`；`origin=ai` 时存在。MM 同步写 `createdBy = "mm-plugin"` | MM 同步 |
| `enabled` | bool | 启停开关。停用的条目仍列出（整行降透明度 + 「已停用」标签），但采样包目录不会写回 `MaterialDirs` | 登记/同步默认 `true`；界面 ⏻ 切换 |
| `tags` | string[] | 标签（去空、按小写去重）。搜索会命中标签 | 登记传入、界面「详情」后续可扩展（当前无标签编辑 UI） |
| `addedAt` | int64 | 入册时间（Unix 秒）。为 0 时 `Add` 补当前时间 | `Add` / 迁移 `stamp()` |
| `updatedAt` | int64 | 最后修改时间（Unix 秒） | `Add`/`Update`/迁移 |

### 2.3 `runtime`（响应期实况，**不落盘**）

`View = Source + runtime`，`runtimeFor` 在每次列举/取单条时按磁盘重算。它让前端不必自己 stat 文件：

| 字段 | 适用 kind | 含义 |
| :--- | :--- | :--- |
| `absPath` | sf2 | `ResolvePath(path)` 后的绝对路径 |
| `fileName` | sf2 | 文件名（列表「文件」行显示它） |
| `missing` | sf2 / samplepack | 文件不存在、或路径为空、或（采样包）所有目录都统计不到内容 |
| `size` | sf2 | 文件字节数（界面用 `UI.fmtSize` 格式化为 `31.0MB` 之类） |
| `presetCount` | sf2 | 读 SF2 的 `pdta/phdr` 得到的预设数（读不到就不填） |
| `sampleDirs` / `sampleFiles` | samplepack | 目录数与**一层**内的音频文件数（隐藏文件跳过；不可访问的目录不计入、也不判缺失） |

SF2 元数据读取是"只 seek 需要的块"：`sf2info.go` 只走 RIFF 块头，`INAM` 取名、`PHDR` 数预设（每记录 38 字节，末条 EOP 不计），预设读取上限 65536 条、文本上限 1024 字节、RIFF 声明长度越界时以实际文件长度为准。`ReadSF2Info` 只取数量，`ReadSF2Presets` 取完整列表；两者都按**不区分大小写**匹配子块 id（`phdr`/`PHDR` 都认）。

预设 id 统一是 `"<bank>:<program>"`；`ParsePresetID` 同时兼容历史 IndexedDB 格式 `sf2_<bank>_<program>[_idx]`。

## 3. 后端设计（`internal/soundlib`）

### 3.1 分层

| 文件 | 职责 |
| :--- | :--- |
| `soundlib.go` | 领域模型与常量：`Source`/`Runtime`/`View`/`Registry`、kind/origin/category 常量、路径转换（`StorePath`/`ResolvePath`）、id 生成（`makeID`/`slug`）、排序（`SortSources`/`SortViews`）、SF2 与音频扩展名判定、`runtimeFor` |
| `store.go` | 存储与 CRUD：`Load`/`saveLocked`、`List`/`Get`/`Add`/`Update`/`Delete`、`normalizeSource`/`normalizeDirs`、`EnsureSF2Source`/`RemoveSF2ByPath`、`DirsForPack` |
| `migrate.go` | 启动迁移与兼容镜像：`Migrate`（扫 `Library/soundfonts` + `MaterialDirs`）、`SyncMaterialDirs`、`flattenPackDirs` |
| `sf2info.go` | SF2 最小元数据解析（名称/预设数/预设表）与预设 id 解析 |
| `mm_install.go` | MM 插件目录 → 注册表条目同步（`SyncInstalledMM`/`SyncAllInstalledMM`/`UninstallMMSource`/`ListInstalledMM`） |

包级约束：`store.go` 的 `mu sync.Mutex` 串行化"读-改-写"。HTTP handler、启动迁移、插件安装三处都经过它，避免两个并发请求各读旧快照、后写覆盖先写。

### 3.2 原子写与容错

```go
tmp := fmt.Sprintf("%s.%d.tmp", FilePath(), time.Now().UnixNano())  // 唯一临时名
os.WriteFile(tmp, raw, 0o644)
os.Rename(tmp, FilePath())                                          // 原子替换
```

- **唯一临时名**是必须的：固定 `.tmp` 会让两个并发写互相踩踏（一个 rename 后另一个的 fd 已失效）；
- 写前 `MkdirAll(config.LibraryDir)`；
- rename 失败会 `Remove(tmp)` 清理；
- `Load` 对"文件不存在 / JSON 损坏 / version ≤ 0 / sources 为 null"一律**返回空注册表而不是错误**：注册表是缓存性质的元数据，不该让应用起不来。

### 3.3 ID 生成规则

```go
makeID(prefix, name, key) = prefix + "_" + slug(name) + "_" + hex(sha256(lower(key))[:3])
```

| 组成 | 规则 |
| :--- | :--- |
| `prefix` | `sf2` / `pack` / `vst3` / `mm` / `src`（未知 kind 用 `src`），见 `idPrefix` |
| `slug(name)` | 转小写并去首尾空白；保留 `a-z0-9`、`-`、`_` 与 **CJK**（`\u4e00`~`\u9fff`，中文名保留便于人工识别）；其它字符折叠为**单个** `_`；去掉首尾 `_`；截断到 24 字符；结果为空则用 `item` |
| `hex(...)` | `key` 先转小写并把 `\` 换成 `/`，再取 sha256 前 **3 字节**（6 位 hex） |
| `key` | `sourceKeyOf`：有 `path` 用 path；否则用 `dirs[0]`；再否则用 `name`。短哈希保证"同目录下同名不同后缀的文件"与"移动后的文件"不会互相覆盖 |

例：`Library/soundfonts/GeneralUser GS v1.471.sf2` 会得到 `sf2_generaluser_gs_v1_471_<6 位 hex>` 形状的 id（`slug` 把空格与点折叠成 `_`，24 字符截断）。

两条例外：

- **MM 插件不用 `makeID`**：`SyncInstalledMM` 用确定性 id `<插件 id 里的点换成下划线>@<version>`（例如 `com_melodymate_example_gain@1.0.0`），判重也按这个 id 而不是按路径——因为 `normalizeSource` 会改写 `Path`，按路径比会漏判；
- **SF2 上传**走 `EnsureSF2Source`：同路径条目已存在时**原样返回**（`created=false`），不覆盖用户改过的名称/标签。

### 3.4 路径约定

| 函数 | 行为 |
| :--- | :--- |
| `StorePath(abs)` | 绝对路径在数据根之内 → 记相对路径（正斜杠，便于整目录搬迁/换盘符）；根外 → 记绝对路径 |
| `ResolvePath(stored)` | 绝对路径直接 `Clean`；相对路径拼到 `config.ProjectRoot` 下 |
| `SoundFontDir()` | `<Library>/soundfonts`，与旧上传通道 `handler_soundfont.go` 的落盘目录一致 |
| `IsAudioPath(p)` | 按扩展名判定音频：`.wav .wave .mp3 .ogg .oga .flac .m4a .aac`（与 `handler_arrangement.go` 的 HTTP 白名单同源） |

### 3.5 启动迁移规则（`soundlib.Migrate()`）

入口在 `main.go`（启动时一次，幂等，失败只记日志不阻断启动）；设置页「↻ 重新扫描」走 `POST /api/sound/migrate` 复用同一函数。

```
Migrate()
├─ 1. 扫 Library/soundfonts/
│     · 只看 .sf2 / .sf3（isSF2Name；目录跳过）
│     · 已登记过的路径（ResolvePath 后小写比较）跳过；id 已存在也跳过
│     · 名称 = 文件名去扩展名；origin：文件名去空格后含 "generaluser" → builtin，否则 user
│     · addedAt/updatedAt = 当前时间
├─ 2. settings.MaterialDirs → 采样包条目
│     · 若已有 origin=builtin 的采样包条目则复用它，否则新建「默认素材」(DefaultPackName)
│       （id = makeID("pack", "默认素材", "material_dirs")）
│     · 新目录并入 dirs（normalizeDirs 去重）
└─ 3. 反向镜像 syncMaterialDirsLocked()
      · 汇总**启用中**采样包的 dirs → 与 settings.MaterialDirs 比较（忽略顺序与大小写）
      · 有变化就 SaveSettings 写回（素材树 /api/arrangement/dirs 仍读该字段）
```

返回值 `MigrateResult{soundFonts, packs, dirs, changed}`；`changed` 为真时落盘注册表并打日志（`[soundlib] 音源注册表已更新`）。接口 `POST /api/sound/migrate` 直接把 `result` 与最新 `sources` 一起返回，设置页据此提示「音色库 +N，采样包 +N，目录 +N」。

迁移的边界：

- 只补"磁盘上有、注册表里没有"的条目；不删条目、不改已有条目的名称/标签；
- `Library/soundfonts` 目录不存在时不是错误（`os.IsNotExist` 静默跳过）；
- 幂等：没有新东西时不写盘。

## 4. HTTP API

### 4.1 通用门槛（`internal/server/router.go`）

| 门槛 | 规则 |
| :--- | :--- |
| Host | 只接受 `127.0.0.1` / `localhost` / `::1` / `wails.localhost`，其余 403「非法 Host」 |
| Origin | 空（非浏览器或同源 GET）放行；其余只接受本机回环与 `http://wails.localhost` |
| 启动令牌 | 所有 `/api/` 请求必须带 `X-MM-Token`（与 `/api/bootstrap.js` 返回的 `token` 一致），否则 401；豁免路径只有 `/api/bootstrap.js`、`/api/health`、`/api/version`、`/api/engine/plugins/ui` |
| 请求体上限 | `/api/sound/import/sf2` → 288 MiB（handler 内部 256 MiB 限流）；其它 `/api/sound/*` → 8 MiB；`/api/audio/*` → 288 MiB |
| 强制更新闸门 | 必要更新未完成时，非 GET 请求返回 426（GET 一律放行） |

### 4.2 注册表与采样包（`handler_sound.go`，注册于 `/api/sound/`）

| 方法 | 路径 | 请求关键字段 | 成功响应 | 主要错误 |
| :--- | :--- | :--- | :--- | :--- |
| GET | `/api/sound/sources?kind=&q=` | `kind` 可选（`sf2`/`samplepack`/`vst3`/`mm`），`q` 关键词（匹配名称/厂商/标签/路径/目录，大小写不敏感） | `{version, sources:[View…]}` | — |
| POST | `/api/sound/sources` | `{kind:"samplepack", name?, path?, dirs[], tags[], vendor?}`；`path` 会并入 `dirs` | `{source}` | 400「无效的请求体」/「目录路径不能为空」/「目录不存在或不可访问: <d>」；非 samplepack → 400「该音源种类请通过导入/扫描接口添加」 |
| PUT / POST | `/api/sound/sources/{id}` | 只接受白名单字段 `{name?, vendor?, enabled?, dirs?, tags?}` | `{source}` | 400（名称为空 / 目录不可访问）、404「音源不存在」 |
| DELETE | `/api/sound/sources/{id}?file=1` | `file=1` 且条目是 SF2 时连带删磁盘文件（仅当文件位于 `Library/soundfonts` 内） | `{ok, source, deletedFile}`；文件删不掉时 `{ok, source, deletedFile:false, detail}` | 404「音源不存在」、500「删除音源条目失败」 |
| GET | `/api/sound/presets?id=` | 条目 id（必须是 sf2 且文件存在） | `{id, name, presets:[{id,name,bank,program}], presetCount}` | 400「缺少 id 参数」/「该音源不支持预设列举」、404「音源不存在」/「音色文件不存在」、500「解析 SF2 预设失败」 |
| GET | `/api/sound/samples?pack=&sub=` | `pack` 必须是 samplepack 条目；`sub` 是相对子路径 | `{pack, root, sub, dirs:[{name,type}], files:[{name,type,size,ext}]}`（`files` 只含音频扩展名，`ext` 是 MIME，取自 `handler_arrangement.go` 的 `arrangeAudioExt`；隐藏文件跳过，两侧按名排序） | 400「缺少 pack 参数」/「非法的子路径」/「读取目录失败」、403「路径不在采样包目录内」、404「采样包不存在」/「采样包未配置目录」 |
| POST | `/api/sound/import/sf2?name=<文件名>` | body = SF2 原始字节（`application/octet-stream`） | `{saved, bytes, source, added}` | 413「SF2 文件超过 256MB 上限」、400「接收上传数据失败，请重试」/「不是有效的 SF2 文件」/「SF2 文件不完整（RIFF size 与实收数据不符）」、500「保存失败」/「音色已保存，但登记音源失败」 |
| POST | `/api/sound/reveal` | `{id}` | `{ok, path}` | 400「缺少音源 id」/「该音源类型不支持定位文件」、404「音源不存在」/「音色文件不存在」/「采样包目录不存在或不可访问」、500「打开位置失败」 |
| POST | `/api/sound/migrate` | 空 body | `{result:{soundFonts,packs,dirs,changed}, sources:[…]}` | 500「扫描音源失败」 |

补充规则：

- `POST /api/sound/sources` 成功后会调用 `soundlib.SyncMaterialDirs()`；`PUT` 与 `DELETE` 同样（`DELETE` 也会清镜像目录）；
- `import/sf2` 的落盘走"消毒文件名 + tmp/rename"，并复用 `handler_soundfont.go` 的三层校验（魔数 `RIFF....sfbk`、RIFF 声明长度与实收字节一致、256MB 上限）；保存后调用 `EnsureSF2Source` 入册；
- 旧通道 `POST /api/audio/soundfonts` 仍保留，且同样会登记注册表条目（`handler_soundfont.go` → `EnsureSF2Source`），`DELETE /api/audio/soundfonts?name=` 会按路径移除条目。

### 5.2 条目卡与六态

条目结构：`[kind 徽标] [名称 + ✨AI + 「已停用」/「文件缺失」标签 / 元信息行 / 路径行] [hover 浮出操作列]`。

| 状态 | 触发 | 表现 |
| :--- | :--- | :--- |
| hover | 鼠标悬停条目 | 边框加深 + 背景 `--color-bg-alt`；操作列由 `opacity/transform` 显现（`:hover`、`:focus-within`、`.selected` 三种触发） |
| focus-visible | 键盘聚焦条目/按钮 | 条目：`--color-primary` 边框 + 2px `--color-primary-soft` 外环；图标按钮：同款外环；行内 `tabIndex = -1`，聚焦由 `sndSelect` 驱动 |
| active | 按下图标按钮 | `transform: scale(0.92)` |
| disabled | 请求进行中 | `.snd-icon-btn:disabled { opacity: .4; cursor: not-allowed }`；重新扫描时 `#sndRescanBtn` 禁用并把文案换成「⟳ 扫描中…」，同步/预览/安装按钮同样在请求期间禁用；下拉里的未开放项用 `.snd-option-soon`（灰、`cursor: not-allowed`、hover 不变色） |
| loading | 面板首次加载 / 重新扫描 | 列表区先渲染 `libEmptyHint("正在加载音源列表…")` 占位行（`.dim.lib-file-empty`）；重新扫描期间按钮禁用 + 文案切换 |
| empty | 组内无条目 / 加载失败 | 组内空态是 `.snd-empty`（虚线框 + 引导文案）；面板级加载失败也是 `libEmptyHint`（「音源列表加载失败：<原因>」） |

另外三种**语义态**：`.selected`（键盘当前项，青边 + 外环）、`.is-off`（停用，整行 `opacity: .55`，操作仍可用）、`.is-missing`（文件缺失，路径行变 `--color-danger`）。

元信息行（monospace 小字）：SF2 显示「预设数 · 大小」；采样包显示「N 个目录 · N 文件」；再拼 `vendor` 与来源标签（`AI` / `内置` / `用户`）。路径行：SF2 显示文件名（`title` 是绝对路径），采样包显示目录列表（`title` 是换行拼接的完整列表）。

操作列四个按钮（MM 插件多一个）：

| 按钮 | 类 | 行为 |
| :--- | :--- | :--- |
| `▷` 试听 | `action-audition` | 引擎 29 轨：`loadSoundFont(diskPath, 29)` → `setTrackPreset(bank, program)`（取该库首个预设）→ `noteOnTrack(29, 60, 100)`，**1.2 秒后自动 noteOff**；播放中按钮加 `.playing` 脉冲（`snd-pulse 0.8s`）；再点一次立即停止；引擎未就绪 toast「✗ 音频引擎未就绪，试听不可用」 |
| `ⓘ` 详情 | `action-detail` | 打开详情弹窗 |

| `⏻`/`◻` 启停 | `action-toggle` | `PUT /api/sound/sources/{id}` 改 `enabled` |
| `🗑` 删除 | `action-del danger` | 二次确认（`UI.confirm`）→ 先播 `.snd-leave` 收拢动画 0.18s（reduced-motion 下直接执行）→ `DELETE /api/sound/sources/{id}`；**SF2 会连带删磁盘文件**（提示里写明）；MM 条目走卸载语义（`POST /api/engine/plugins/uninstall`，文案「卸载插件（删除安装目录并清理注册表）」） |

### 5.6 动效口径

曲线名一律引 [前端设计必读](前端设计必读.md) 的四条主曲线；实现里只对 `transform` 与 `opacity` 做动画（`npm run check:sound` 会拒绝 `.snd-*` 规则里出现 `height` 过渡与硬编码 hex）。

| 事件 | 关键帧/过渡 | 曲线 | 时长 |
| :--- | :--- | :--- | :--- |
| 条目进场 | `snd-in`：`opacity 0→1`、`translateY(6px)→0`、`scale(.98)→1`，`--snd-delay` 提供 Stagger | `cubic-bezier(0.34, 1.45, 0.64, 1)`（**Bouncy Pop**） | 0.40s，阶梯 40ms（`min(idx,12) × 0.04s`） |
| 条目删除 | `snd-leave`：收拢淡出（`scaleY`），`pointer-events: none` | `cubic-bezier(0.55, 0, 0.85, 0.36)`（**Snappy Collapse**） | 0.18s |
| 组头折叠箭头 | `transform: rotate(-90deg)` | `cubic-bezier(0.16, 1, 0.3, 1)`（**Fluid Glide**） | 0.18s |
| 操作列显现 | `opacity 0→1` + `translateX(4px)→0`（hover / focus-within / selected 三种触发） | `ease` | 0.15s |
| AI 徽标呼吸光 | `snd-ai-breathe` | `ease-in-out` | 2s 循环 |
| 试听脉冲 | `snd-pulse`（按钮 `.playing`：`scale(1)→1.12→1`） | `ease-in-out` | 0.8s 循环 |
| 拖拽浮层 | `snd-hint-in`：`opacity 0→1` + `translateY(4px)→0`（配 `display: block` 切换） | `ease-out` | 0.15s |

`@media (prefers-reduced-motion: reduce)` 段把条目进场/退场、AI 呼吸光、试听脉冲、拖拽浮层动画全部关掉，并把操作列与箭头的过渡降级为瞬时。

注：计划书 §4.2/§4.10 写的是"`spring-in` + Stagger 40ms / Natural Spring"，实现用的是 Bouncy Pop 曲线（`snd-in`）；以本文与 `style.css` 为准。

### 5.7 其它交互细节

- 搜索 200ms 防抖后整表重绘（列表规模小，重绘比增量 DOM 便宜）；
- 排序：`name`（默认，小写比较）/ `added`（`addedAt` 倒序）/ `size`（`runtime.size` 倒序）；
- 试听与删除都是"事件委托"绑定在 `#sndGroups` 上（行会被整批重绘）；
- 注册表变化会通过 `SoundRegistry.onChange` 广播，本面板订阅后重绘——别处（机架/素材库/AI）改动也能即时反映。

## 6. 与其它模块的契约

### 6.1 `frontend/src/soundlib.ts`：全局唯一出口

`window.SoundRegistry` 是单例，页面加载即预取一次。内存缓存 + 写操作后整体重取（`reload()` 清预设缓存并广播 `onChange`）。

| 方法 | 用途 | 主要调用方 |
| :--- | :--- | :--- |
| `load(force?)` / `reload()` / `all()` | 拉取与访问全量条目 | 设置页、机架、素材库、钢琴窗 |
| `list(kind)` / `enabledOf(kind)` / `get(id)` / `query(kind, q)` / `countByKind(kind)` | 过滤与检索 | 设置页分组、机架过滤器、素材库音源页签 |
| `kindMeta(kind)` / `kindOrder()` / `isPluginKind(kind)` | 徽标/图标/分组顺序元数据 | 设置页、素材库、机架 |
| `isAI(src)` / `isBuiltin(src)` / `originLabel(src)` | 来源判定与文案（✨AI 徽标五处统一） | 设置页、机架、素材库、参数面板、插件窗口标题 |
| `presets(id)` / `firstPreset(id)` | SF2 预设（`bank:program`），带缓存与并发合并 | 音源选择器、机架预设列、钢琴窗 |
| `importSf2(file)` | 上传 SF2：`POST /api/sound/import/sf2` → 顺带写 IndexedDB 解码缓存 → `reload()` | 设置页、钢琴窗音源库弹窗（`chat.ts`） |
| `addSamplePack(name, dirs)` / `update(id, patch)` / `setEnabled(id, on)` / `remove(id, {file})` / `rescan()` | 写操作（每次成功后 `reload()` 并广播） | 设置页 |
| `samples(packId, sub?)` | 采样包内容列举 | 素材库采样页签 |
| `diskPathOf(src)` | 条目的磁盘绝对路径（引擎模式发声用） | `audio_engine.ts`、设置页试听 |
| `browserRecord(src)` | 取浏览器模式（WebAudio）解码缓存记录 | 钢琴窗 |
| `parsePresetId(id)` | 预设 id → `{bank, program}`，兼容 `"0:48"` 与 `"sf2_0_48_2"` | `audio_engine.ts`、`arrange.ts`、`pianoroll.ts` |
| `metaText(src)` | 列表用的元信息文本（大小/预设数/目录数/文件数） | 素材库、机架 |

消费点（`grep SoundRegistry frontend/src`）：

- **输出机架** `frontend/src/arrangement/rack.ts`：条目解析（`ArrRack.resolve` 把 `{itemId,presetId}` 解析成 voice）、kind 徽标、AI 徽标、预设列、空态引导；
- **素材库** `frontend/src/arrangement/material.ts`：采样页签按包分组、「音源」页签（`enabledOf` 分别取 `sf2`/`vst3`/`mm` 再拼接）、「效果器」页签（`category === "effect"` 的插件条目）、右键菜单「打开文件位置」；
- **钢琴窗** `frontend/src/pianoroll/pianoroll.ts`：音色列表改为注册表 `list("sf2")` + `presets()`，选择结果写回 `arrangement.pianoRoll`（`persistSource` → ops `setPianoRoll`）；删除音色走 `remove(id,{file:true})`；
- **引擎/浏览器发声** `frontend/src/arrangement/audio_engine.ts`：引擎模式优先用 `diskPathOf(reg)` 直供引擎（换机器/清缓存也能发声），拿不到才回落 IndexedDB 记录与相对路径推导；
- **对话页音源库** `frontend/src/chat.ts`：上传按钮与设置页共用 `SoundRegistry.importSf2`。

### 6.2 为什么 IndexedDB 降级为"浏览器模式解码缓存"

引擎模式下发声只需要"磁盘路径 + `bank:program`"，注册表条目两者都有，于是 IndexedDB 的必要性只剩一件事：**WebAudio 需要采样数据本身**（浏览器模式没有原生引擎，必须把 SF2 字节解码到内存）。

现状（`frontend/src/pianoroll/sound_library.ts`）：

- 数据库 `MelodyMate_SoundLibrary`（版本 1，对象仓库 `soundfonts`，主键 `id`，索引 `name`/`createdAt`）；
- 记录字段：`id`（`sf2_<时间戳>_<随机>`）、`name`、`size`、`presets`、`data`（ArrayBuffer）、`diskPath`（服务器落盘绝对路径）、`sourceId`（**与注册表条目的桥**）、`createdAt`；
- `recordForSource(sourceId, name)`：先按 `sourceId` 直配，再按 `name` 回退（历史记录没有 `sourceId`）；
- `saveSoundFont` 记录 `sourceId`；列表接口会剥离 `data` 字段（游标逐条读，避免 `getAll` 把几十 MB 的缓冲一次性物化）；
- 仍保留的旧通道：`saveSoundFont` 会顺带 `POST /api/audio/soundfonts` 拿 `saved`/`source.id`，`deleteSoundFont` 会顺带 `DELETE /api/audio/soundfonts?name=`。

结论：IndexedDB **可以按磁盘重建**，不做迁移、不做真源；它只在浏览器模式与"未入册的历史工程"里兜底。

## 7. 迁移与兼容

### 7.1 老用户数据怎么入册（两条路，都不需要用户干预）

```
路径 A：旧安装目录 → 新数据根（仅改名版本需要）
   internal/app/migrate.go 的 MigrateLegacyInstall/MigrateLegacyData
   · 触发条件：新数据根没有 settings.json、也没有 melodymate-migration.json
   · 旧目录候选：%LOCALAPPDATA%\Programs\AI_MIDI，以及新数据根同级的 AI_MIDI\
   · 复制（不删源）：projects/、Library/user/、Library/soundfonts/、output/、settings.json
   · 结果写入 <数据根>/melodymate-migration.json，前端经 GET /api/migration 提示一次

路径 B：磁盘 → 注册表（每次启动都跑，幂等）
   main.go → soundlib.Migrate()
   · Library/soundfonts/*.sf2|*.sf3 逐个入册（§3.5）
   · settings.MaterialDirs → 「默认素材」采样包条目
```

所以老用户的 SF2 与素材目录**首启即可见**，不需要重新上传；注册表删掉也能由路径 B 重建。

### 7.2 旧 IndexedDB 什么时候可以删

`frontend/src/app.ts` 顶部注释写明了口径：旧版 localStorage 键迁移到 `melodymate-*`，而 **`AI_MIDI_SoundLibrary` 要等声音管理确认磁盘音源已入册后再删**。当前代码只实现了 localStorage 键迁移（`migrateLegacyStorage`，只在新键不存在时复制、不删旧键），**没有**自动删除旧 IndexedDB 的逻辑；IndexedDB 数据库名本身已经改成 `MelodyMate_SoundLibrary`。也就是说：删除旧库是"确认入册后的人工/后续动作"，不是启动时的自动行为。

### 7.3 AI_MIDI → MelodyMate 改名中音源部分的处理

| 项 | 处理 |
| :--- | :--- |
| 数据文件 | `Library/soundfonts/`、`Library/user/`、`projects/` 整体复制到新数据根（§7.1 路径 A），原目录保留可回滚 |
| 采样目录配置 | `settings.json` 一起复制，`MaterialDirs` 由路径 B 变成「默认素材」条目 |
| 注册表 | 新文件 `Library/registry.json`，无需从旧版迁移（旧版没有这个概念），全部由路径 B 生成 |
| 预设引用 | 老工程的 `presetId` 有两种写法：注册表格式 `0:48` 与历史 IndexedDB 格式 `sf2_0_48_2`，`ParsePresetID`（后端）与 `SoundRegistry.parsePresetId`（前端）都解析；引擎侧只认 `bank/program` |
| 存储键 | localStorage `ai-midi-*` / `aimidi_*` → `melodymate-*`（含 `melodymate_snd_collapsed` 折叠状态，属于本页签自己的键） |
| 首启提示 | `GET /api/migration` 返回一次性结果：有待提示记录时 `{pending:true, from, files, soundfonts}`，否则 `{pending:false}`（`announced` 标志写在 `<数据根>/melodymate-migration.json` 里，不出现在响应中）。前端 toast 原文「已从 AI_MIDI 迁移 N 个文件 / N 个音源」 |

### 8.2 手工验收步骤（桌面版）

1. **首启入册**：把任意 `.sf2` 拷进 `Library/soundfonts/` → 启动应用 → 设置 → 声音管理：SF2 组出现该条目，元信息行有「N 预设 · 大小 · 用户」；`Library/registry.json` 里出现对应条目。

4. **重新扫描**：手动把 `.sf3` 拷进 `Library/soundfonts/` → 点「↻ 重新扫描」→ toast 里出现「音色库 +1」。
5. **搜索与排序**：输入厂商/标签片段 → 组内即时过滤、空组隐藏、底部显示「匹配 M / 共 N 个音源」；切换排序为「大小」→ 顺序变化。
6. **六态与徽标**：鼠标悬停条目 → 操作列浮出；`Tab` 进入列表后按 `↑↓` → 选中项描边与外环可见；AI 插件条目显示 `✨AI` 呼吸光；停用条目整行变淡并显示「已停用」。
7. **详情与打开位置**：`Enter` 或 `ⓘ` 打开详情 → 字段与条目一致；「📁 打开位置」在资源管理器里定位/打开对应路径。
8. **试听**：选中 SF2 条目点 `▷` → 引擎 29 轨发声约 1.2 秒，按钮呈脉冲态；再点一次立即停止；关掉引擎时点 `▷` → toast「✗ 音频引擎未就绪，试听不可用」。
9. **启停与删除**：`⏻` 停用 → 采样包目录从 `material_dirs` 移除（如为采样包）；`🗑` 删除 SF2 → 二次确认后条目收拢淡出，磁盘文件同时被删（确认框文案已写明）。
10. **MM 插件链路**：命令行 `mm install <pkg> --dest Library/plugins` 或让 AI 安装 → 设置页点「↻ 同步已安装插件」→ MM 组出现条目（能力/哈希/来源可见）→ `ⓘ` 详情、`🎛` 打开承载窗、`🗑` 卸载（走 `/api/engine/plugins/uninstall`）。
11. **双主题与降级**：暗蓝 / 暖纸两套主题逐屏走查（含 hover、focus、空态、加载态）；系统开启"减弱动态效果"后条目不再位移/缩放、AI 呼吸光静止，功能不受影响。
12. **重建验证**：关闭应用 → 删除 `Library/registry.json` → 重启：条目由磁盘与 `material_dirs` 重新生成（注册表是缓存，不是真源）。
