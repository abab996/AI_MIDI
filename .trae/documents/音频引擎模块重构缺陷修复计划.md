## 一、概要

「刚刚完成的重构」= 主仓与引擎仓两边的**未提交改动**（主仓最后提交 b5b4afe "M2 阶段五"，引擎仓最后提交 701b916）。重构方向正确（串行事务客户端、实时音符走二进制 Midi 帧、混音器、设置面板），但**进行到一半被中断**，当前状态：

1. **Go 侧整个项目编译失败**（`internal/engine` 包未定义类型 + 参数顺序错误，连带 server/app/main 全部无法构建）；
2. **新 client.go 的线格式与引擎 C++ 实现相反**（帧长度差 1 字节），即使编译修好 IPC 也全断；
3. **引擎源码出现管道名回归**（丢了 PID 后缀），且与 12:17 构建的 exe 不一致——重建引擎后 Go 将永远连不上管道；
4. 前端设置页存在重复脚本块、设备下拉永远为空、后端切换静默失效等问题。

已有运行时验证：`bin/aimidi-engine.exe`（12:17 构建）本身**完全正常**——实测管道建立 + hello 往返成功。问题全部在两侧源码的半成品状态。

### 2.2 关键证据

- **编译失败**（实测 `go build ./...`）：
  - `client.go:64/240/277: undefined: Response`、`client.go:68: undefined: Request`、`client.go:204: undefined: EngineInfo`

- **线格式矛盾**：`protocol.go` EncodeFrame/DecodeFrame、`protocol_test.go`（断言 `n == len(payload)+1`）、`tools/pipe_probe`、`tools/engine_smoke`、引擎 `PipeServer.cpp::writeFrame`（`length = size + 1`）全部采用「长度含类型字节」；唯独新 `client.go` 的 writeFrame/awaitResponse 用「长度不含类型字节」→ 每帧少 1 字节且流错位。

- `e2e_run.log`（11:44）无限重启循环即上述半成品状态叠加旧引擎 exe 的产物；当前 exe + 修复后源码即可消除。

## 四、修复方案（逐文件）

### 4.1 Go 侧

**A. `internal/engine/types.go` —— 补齐消息类型（修 #1）**

```go
// Request 控制请求（Go → Engine）
type Request struct {
    ID     float64        `json:"id"`
    Method string         `json:"method"`
    Params map[string]any `json:"params"`
}

// Response 控制响应（Engine → Go）；ok=false 时 Error 非 nil
type Response struct {
    ID     *float64        `json:"id"`
    OK     bool            `json:"ok"`
    Result json.RawMessage `json:"result"`
    Error  *EngineErrorBody `json:"error"`
}

type EngineErrorBody struct {
    Message string `json:"message"`
}

// Err ok=false 时返回业务错误
func (r *Response) Err() error {
    if r.OK { return nil }
    msg := "unknown error"
    if r.Error != nil { msg = r.Error.Message }
    return fmt.Errorf("engine: %s", msg)
}

// EngineInfo hello 应答内的引擎信息
type EngineInfo struct {
    Name            string   `json:"name"`
    Version         string   `json:"version"`
    ProtocolVersion uint32   `json:"protocolVersion"`
    Capabilities    []string `json:"capabilities"`
}
```

**B. `internal/engine/client.go` —— 恢复正确线格式与看门狗 I/O（修 #4 #5 #16）**

- `writeFrame(typ, body)`：改为 `frame := EncodeFrame(typ, body)`，单次 `conn.Write(frame)`（保持 mu 串行；写带 5s 看门狗 goroutine + select，超时 markDead，参照 HEAD 实现）。
- `awaitResponse(id, timeout)`：读循环改为「辅助 goroutine 读 4 字节长度 + 按长度读整 payload（长度含类型字节，等价 DecodeFrame 语义）→ select 带 deadline」；超时 markDead 并返回错误（连接不可信，由 supervisor 重建）。事件帧仍走 `emitEvent`。
- 删除对同步管道 `SetReadDeadline` 的依赖。
- `SendMidi(status, data1, data2)`：载荷改为 `[]byte{status, data1, data2}`（引擎修复 #7 后 payload=4 字节即可带 velocity）。`Client.NoteOn/NoteOff` 包装保持不变（0x90|ch / 0x80|ch 布局正确）。
- `handshake`：解析 `resp.Result` → EngineInfo，校验 `ProtocolVersion == 1`（保留现逻辑）。

**C. `internal/engine/supervisor.go` —— 全量迁移到新签名（修 #2 #3 #10 #18 #19 #21）**

- 10 处调用点改为 `cli.Request(method, params, timeout)`；凡需要结果的都先 `if err != nil` 再 `if err := resp.Err(); err != nil`，然后用 `resp.Result` 解析：
  - ListDevices：`json.Unmarshal(resp.Result, &rawList)`
  - LoadSoundFont：`json.Unmarshal(resp.Result, &res)`（res 只留 `Loaded bool`；引擎已不发 error 字段，失败文案兜底"引擎加载音色失败"）
  - RequestRaw：`return resp.Result, err`（handler_audio.go 的 currentSummary 查询无需改动）
  - OpenControlPanel：补 `resp.Err()` 检查
- `NoteOn/NoteOff`：改为 `cli.SendMidi(0x90|channel, key, velocity)` / `cli.SendMidi(0x80|channel, key, 0)`（二进制帧、不等待响应，符合协议"实时消息禁止 JSON 化"）。
- `Ready(timeout)`：state 为 `StateDisabled` 时立即返回错误（引擎禁用不等待）；`StateFailed` 且为驻留态（exe 缺失）同样快速失败。
- `ResolveEnginePath`：candidates 为空时兜底返回 `"bin/aimidi-engine.exe"`。
- runOnce：仅非首次会话才 `Restarts++`（加 `firstSession bool`）。

**D. `internal/server/handler_soundfont.go`（修 #17）**

- `cap := 0; if req.ContentLength > 0 { cap = int(req.ContentLength) }; buf := make([]byte, 0, cap)`。

## 五、关键决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 修复策略 | **前向修复**（不执行 rollback_to_stable_m2.bat） | 重构含真实价值：声部爆炸/循环相位/迟到解码等前端修复、混音器、控制面板、自测页；回滚会全部丢失 |
| 实时音符通道 | Go 改走**二进制 Midi 帧**（不恢复引擎 JSON noteOn/noteOff） | 协议文档明确"实时高频消息必须走二进制类型，禁止 JSON 化"；引擎删除 JSON 方法是正确方向 |
| 错误格式对齐 | **引擎改为文档格式**（error 为对象） | 文档是"唯一权威来源"；Go/冒烟测试已按对象解析 |
| 帧编解码 | client.go **复用 protocol.go 的 EncodeFrame** + 恢复 HEAD 看门狗读模型 | 与引擎/文档/测试工具四方一致；避免再次手写出错 |
| `updateTrackMix` 前端死代码 | 保留不接线 | M3 混音图 WIP，接线属新功能非缺陷修复 |
| 引擎新文件 Transport.h/MixerGraph.h/PluginHost.h | 不动 | MixerGraph/Transport 已被 EngineAudioDevice 引用属当前功能；PluginHost 为未接线 WIP，编译验证即可 |
