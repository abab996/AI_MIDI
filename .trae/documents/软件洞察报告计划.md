## 现状分析（Phase 1 探索结论）

### 产品形态
- 三页 MPA：`index.html`（快捷操作/单次任务）→ `chat.html`（档案库 + 对话工作台 + 编曲窗 + 钢琴窗抽屉，核心页面）→ `settings.html`
- 页面间通过 `<a href>` 整页跳转，`sessionStorage` 传递导航方向做转场动画；主题切换需在每页 head 内注入防闪烁脚本（MPA 的典型代价，出现于 3 个 html）
- 视觉为「工程图纸/技术蓝图」风：暖纸/暗夜蓝双主题、橙色主按钮 + 3D 硬阴影、等宽字体大写按钮、stamp 印章装饰、①②③编号站、图纸网格背景

### 技术架构（Go 侧，结构尚可）
- `internal/`：app(Wails 绑定)、chat(对话管线)、config、engine(命名管道 IPC + supervisor)、llm、mcp、midi(SMF)、project(项目/历史/工作区)、server(HTTP)、tasks
- 音频引擎为独立原生子进程（JUCE），主进程只发命令；已有单实例保护、Splash、Job Object 清理

### 关键事实（报告论据基础）
- 前端无框架、无构建、无模块化：`chat.js` 137KB、`pianoroll.js` 115KB、`arrange.js` 101KB，全局脚本依次加载
- `docs/代码检查报告-2026-08-22.md` 已记录一批已修复缺陷（编曲窗打不开、播放卡顿、任务状态异常等），本报告需区分"已知已修复"与"新发现"
- `.trae/documents/` 三个修复计划记录了双引擎孤儿进程、播放静默（SF2 未加载）、M3 阶段 Transport/MixerGraph 未接线等遗留问题
- `前端设计必读.md` 定义了动效哲学（贝塞尔曲线、仅 transform/opacity、无障碍降级），是既有设计约定

## 执行步骤

### Step 1 — 深度代码审读（本地，只读）

补齐 Phase 1 未覆盖的细节，重点文件与关注点：

**前端**
- `frontend/js/chat.js`（137KB，分段读）：初始化流程、消息渲染、事件绑定方式、错误处理、加载态/空态、与后端轮询或 SSE 的耦合
- `frontend/js/pianoroll/pianoroll.js`：工具切换、快捷键表、滚轮/缩放语义（Ctrl 缩放 vs 纵向滚动）、undo/redo 深度、自动保存策略
- `frontend/js/arrangement/arrange.js`：轨道/Clip 交互、与钢琴窗状态同步、保存链路
- `frontend/js/app.js`、`workbench.js`、`tasks.js`、`theme.js`、`settings.js`：MPA 重复代码、轮询逻辑
- `frontend/js/pianoroll/{tools,synth,soundfont,audio_context,midi_input}.js`、`engine/engine_bridge.js`、`arrangement/audio_engine.js`：双音频路径（Web Audio vs 原生引擎）并存情况
- `frontend/style.css`：通读组件层（按钮/弹窗/抽屉/表格），找不一致 token、行内样式滥用点

**后端**
- `internal/server/handler_*.go`：错误响应一致性、入参校验、并发
- `internal/chat/{pipeline,session,compact,interactive,prompt}.go`：全局 map 与锁、流式中断、历史压缩
- `internal/project/{manager,lifecycle,history,workspace}.go`：文件安全、并发写、崩溃恢复
- `internal/engine/{client,supervisor,global,job_windows}.go`：超时/重连/孤儿进程现状
- `internal/{llm,midi,tasks,mcp}`：重试、sanitize、任务注册
- 测试覆盖盘点：`go test ./...` 的测试文件分布（前端 0 测试）

**文档**
- 通读 `docs/代码检查报告-2026-08-22.md` 全文，标记已修复项，避免报告重复
- `前端设计必读.md`、`docs/编曲窗口设计文档.md`（设计意图 vs 实际落差）

产出：内部问题清单（每条含 文件:行号 + 严重度 + 类别），作为报告第 6-8 章素材。

### Step 2 — 竞品与市场调研（WebSearch）

分三组查询（每组 2-4 次搜索，2026 年现状）：
1. **AI 音乐生成工具**：Suno、Udio、AIVA、Soundraw、Stable Audio 的功能矩阵、编辑能力边界、定价与工作流（prompt→生成→编辑→导出）
2. **专业 DAW 的 UX 惯例**：FL Studio / Studio One / Ableton Live / Cubase 的钢琴卷帘与 Playlist 交互惯例（工具快捷键、滚轮语义、右键菜单、走带条布局）、深色主题规范
3. **AI+DAW 融合形态与桌面工程化**：AI 辅助 DAW 新品（如 WavTool 类）、TME Studio / 网易天音 / SkyMusic 等国内产品；桌面应用自动更新、崩溃上报（Sentry 类）、Wails 应用发布惯例

产出：竞品对比表素材 + 可借鉴的 UX 惯例清单（用于报告第 3、4、5 章）。

报告大纲（章节固定）：
