# MelodyMate 30 项缺陷分阶段修复计划

目标：修复审查报告 F01–F30，覆盖 TypeScript 前端、Go 后端及独立 C++ 引擎仓库。先解决数据丢失，再恢复音频与插件功能，最后完成兼容和集成验收。

## 已确定的原则

- 全部 30 项分阶段修复。
- 保存冲突保留本地草稿及服务端版本，暂停自动保存，由用户选择后继续。
- 浏览器由应用授权打开；授权会话支持刷新、页面跳转和插件窗口。
- 保留现有工程格式的兼容读取；迁移前备份，避免静默丢弃无法恢复的数据。
- 沿用现有界面样式；新增冲突提示支持键盘操作和现有双主题。

## 接口与状态契约

- 编排整份保存必须携带 rev，项目写锁内比较，不匹配返回 409、code=arrangement_conflict、最新 rev 和编排快照；成功返回新版本。
- 每项目最多一个保存请求；维护确认基线、本地编辑、服务端最新版本，三方合并。轨道、机架、剪辑按 ID，FX 按槽位匹配；音符数组、音源引用、轨道顺序整体合并；删除与修改冲突暂停保存。
- 加载、ops、SSE、保存及插件恢复捕获项目 ID 和代际；过期响应不修改当前界面、保存标记和引擎。SSE 累积 changed 并集及最高 rev。
- 插件项目目标使用稳定 trackId，数字索引仅在下发引擎时计算。统一注册表解析格式、版本、插件 ID 和路径。FX 增加可选 sourceId，兼容 plugin 字符串。
- 状态新文件按 trackId 哈希命名，信封记录 trackId、格式和引用；仅在轨道映射和引用匹配时迁移旧索引文件。
- 引擎实例操作串行协调，切换取消旧作业；当前项目同步完成前播放显示等待或失败。

## 验收

- 数据：A/B 延迟响应、旧 ops、保存中编辑、未保存新轨、AI 连续事件、过期 PUT、删除与编辑冲突；双方数据保留；5MB 边界。
- 音频：MM SDK Gain/Synth 与自建 VST3 Gain/Synth；验证样本、wet/bypass、panic、实时/导出乐器一致。
- 生命周期：空工程切换、重排/删除、替换、重开、引擎重启、gain=0；目标和状态正确，实例数量不增长。
- 资源：自定义入口、拆分资源、多版本、外窗消息、未授权引导、刷新/窗口；合法成功，非法拒绝。
- 注册表：重复迁移、禁用刷新、删除后重启、旧工程音源恢复、浏览器实际解码。
- 最终运行 go test 全量与 race、go vet、前端 typecheck 和回归；新增 C++ CTest 并构建引擎；隔离数据目录运行真实浏览器、桌面及离线音频验收。
